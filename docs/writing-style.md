# 叙述约定

> 本文件定义视角、时态、文风、端木技法在本项目的落地形式。agent 写正文和 reviewer 审稿时以此为参照。
> 这些约定不锁进 [[00_世界观/核心设定|世界观]]（不是世界法则，是叙事工艺），可随项目迭代调整，走轻量评审即可。
> 技法中可量化的阈值（三万字、首章 300 字等）已录入 [[docs/audit-checklist]] 作为可核验检查项。
> 
> **端木技法的硬/软分类判据**：可机械化验证的阈值（字数/出现位置/次数统计）→ audit-checklist 硬检查；需人类审美判断的质感（节奏/张力/文风/是否"好看"）→ reviewer 软阻断 + 用户裁决。下方每条技法标注归属类别。

## 端木技法在本项目的落地

以下技法来自端木灵星《小说写作、投稿技巧与经验汇总》，作为本项目的 reviewer rubric 抓手。

### 开篇结构

- `[硬]` 300 字内主角出场、第一章抛出第一个冲突 —— `check_chapters.py` 统计
- `[硬]` 三万字内解决第一个主要矛盾 —— `check_foreshadowing.py` 字数+伏笔闭合
- `[软]` 前三章强化主角存在感、不要开头堆世界观设定 —— reviewer 软阻断

### 悬念与钩子

- `[硬]` 每章末尾必须留钩子（未解张力 / 提问 / 异动）—— 可由 reviewer 逐章检查"章末是否有 hook 标记"
- `[硬]` 伏笔要快速挖出来用掉 —— `check_foreshadowing.py` 已有时效检测

### 战斗描写（如适用）

- `[软]` 细节恰到好处、读者附身视角、适当议论说明原理、意境营造、服务于人物冲突 —— reviewer 软阻断

### 场景代入

- `[软]` 视觉 / 听觉 / 嗅觉 / 触觉立体呈现 —— reviewer 软阻断，"场景生动度"维度

### 矛盾来源（为大纲提供动力判断）

- `[大纲]` ①人物（争夺/情敌/护亲）②家族/地域/天地 ③种族 ④善恶对立 ⑤主角自身需求 —— 非检查项，是大纲规划工具

## 以筠·故事驱动法则（世界观→大纲指导）

以下六条法则来自以筠世界观设计系列 #6，解决"设定一大堆但写不出故事"的瓶颈。它们不替代端木技法（端木管"写出来好不好看"），而是确保"设定本身有故事张力"。

| # | 法则 | 在大纲/写前合同中的落点 |
|---|------|---------------------|
| 1 | **关键设定就是用来失效的**——故事开头只需让世界某个重要系统突然坏掉 | `01_大纲/主线.md` 主线来源 |
| 2 | **世界最骄傲什么，就先让它坏什么**——第一枪打在世界最疼的地方 | `01_大纲/主线.md` 开篇约束 |
| 3 | **最了解系统的人最适合成为故事入口**——不要总让最强的人先发现问题 | `02_人物/<角色>.md` 角色定位 |
| 4 | **让设定主动接触人物**——不要让角色去"了解世界观"，让世界观的失效来撞角色 | 写前上下文包 |
| 5 | **多提问，少解释**——用角色的行动/反应展示设定，不用旁白 | reviewer rubric |
| 6 | **让人物别无选择**——关键情节中角色选择都在"都不好"中被迫选 | 写前达成断言 |

## 文风注册表

> 每个角色在 frontmatter 中绑定 `style_register`，对应一个注册项。写前注入注册到上下文包；reviewer 检查角色对话/叙述是否与注册一致。**这是 reviewer 软阻断项**——属审美判断，但注册表提供了可对照的基线。

### 注册格式

每个注册含四个维度：

| 维度 | 说明 | 示例（武侠注册） |
|------|------|---------------|
| 称谓域 | 角色怎么称呼别人/怎么被称呼 | 师叔/少侠/前辈/施主；禁用：先生/小姐/女士 |
| 器物域 | 日常物件的叫法 | 剑/刀/暗器/丹药/内力；禁用：魔法/卷轴/圣光 |
| 修辞域 | 比喻和意象的来源范围 | 山水/四季/武术/佛道典故；禁用：机械/星球/计算机 |
| 节奏域 | 句长偏好、对话与叙述比重、语气词习惯 | 简练、少感叹号、不押韵；战斗描写可适当铺陈 |

### 示例注册

#### `武侠`（默认，中原武林角色的通用注册）
- **称谓**：师叔/师伯/师兄/师妹、少侠/女侠、前辈/阁下、施主/贫僧
- **器物**：剑/刀/暗器/丹药/内力/轻功/穴位/经脉
- **修辞**：山水意境、四季变换、招式名（诗意或直白）、佛道用语
- **节奏**：简练、非必要不铺陈心理活动、战斗段落可细化、不在对话中长篇解释设定
- **禁用**：西式称谓（先生/小姐/伯爵）、科技词汇、现代口语（OK/搞定/没办法）、欧式长句

#### `西域`（来自西域或更西方的角色）
- **称谓**：大人/阁下/朋友、少主/主人
- **器物**：弯刀/骆驼/香料/药粉/异域乐器；**可以适当混用不同于中原的器物词**
- **修辞**：沙漠/绿洲/商路/星空/异域传说
- **节奏**：可稍繁复、可带翻译腔的短句结构
- **区分规则**：西域角色可以不知道中原的称谓/器物/修辞——**但中原角色不应该说出西域特有的词汇**，除非设定中学过。

#### `宫廷`（朝堂/贵族角色）
- **称谓**：陛下/殿下/大人/臣/下官/微臣
- **器物**：奏折/印绶/朝服/贡品/圣旨
- **修辞**：典故/历史/礼法/天象/君臣之道
- **节奏**：对话注重礼节层级、话中有话；可铺陈排比

#### `市井`（平民/商贩/底层角色）
- **称谓**：客官/掌柜/老兄/小弟/姑娘/婆婆
- **器物**：铜钱/扁担/瓦罐/短刀/锄头
- **修辞**：日常俗语、劳作场景、吃喝拉撒
- **节奏**：短句、口语化、节省修饰

### 使用规则

1. 每个角色绑定一个主注册（`style_register: 武侠`），可选一个副注册（如西域角色在特定场景切到 `西域`）
2. 叙事旁白默认跟随当前 POV 角色的注册——**以 POV 角色的语言习惯来叙述**
3. reviewer 检查时，**同场景不同注册的角色混写时，看其对话/叙述是否各自符合注册**——武侠角色不说西域词、市井角色不说宫廷礼
4. 新注册可随时增加——发现新的文风需求（如"仙侠""科幻"）时在注册表中定义即可
5. 注册的"禁用"项是 reviewer 的可判定信号——正文中出现了禁用词汇 = 文风漂移的客观证据
