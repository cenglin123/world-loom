# 方法卡库

## 要解决的问题

方法论写在常驻文档里，代价随方法论数量线性增长——每一次对话都要带上全部方法，
哪怕这次只用得到其中一条。方法论收得越多，每次推理越贵。

目标是把这条曲线掰平：**知识总量可以一直涨，单次上下文开销基本不涨。**
类比 dense → MoE：路由表常驻，专家按需激活。

## 架构

三层，越往下越贵、越少触发：

| 层 | 是什么 | 常驻？ | 大小 |
|----|--------|-------|------|
| 路由 | `_方法/_索引.md`——每卡一行（一句话 + tags） | 是 | 9 卡约 0.6k 字 |
| 检索 | `method.py find "<自然语言问题>"` → top-k 卡名 + 一句话 | 否 | 单次约 0.2k |
| 展开 | `method.py show <id>` → 整卡 | 否 | 单卡约 1k |

检索是 **BM25 + 中文双字切分**，纯词面、零依赖、无向量。
双链（`相关:`）提供图扩展：`find --hop 1` 带出命中卡的邻居，补词面检索够不到的关联。

## 关键设计决策

### 症状字段

第一版检索有一次明显误排：查询「写到第三卷不知道该写什么了」，
`地形生成法` 压过了 `长篇失速诊断`——两张卡都只命中 `不知`、`什么` 这类功能词双字，
短卡因 BM25 长度归一化胜出。

根因不是参数，是**词汇鸿沟**：作者写卡用术语（"线头过载"），求助者说的是"不知道该写什么了"。
所以每张卡必须写 `症状:`——求助者的原话，权重与标题并列最高。
补上之后同一查询的首位得分 21.5 vs 4.4，五个测试查询全部首位命中。

`method.py check` 把缺 `症状` 当失败拦下：**没有原话钩子的卡，只有作者自己搜得到。**

### 只收方法，不收素材

方法是"怎么做"，素材是"有什么"。生物图鉴、骑士盘点、占卜方式一类不进库——
模型本身就有大量此类常识，收进来既重复又永远收不完，还会把路由表撑坏。

### 常驻的判据不进库

「故事驱动法则」这种任何时候都成立的短判据留在 `docs/writing-style.md`。
**路由的价值在于筛掉当前用不上的东西——永远用得上的东西没有筛的必要。**

### 去重

吸纳前 `method.py dupe "<摘要>"`，按落点判定：同一套步骤换外壳 → 并卡并扩关键词；
多出新判断步骤 → 并卡加步；落点与判据都不同 → 开新卡并互相双链。
`method.py check` 另有全库反查，两张卡过于相似会被拦。

## 素材吸纳

库只解决"用得起"，不解决"长得大"。要能不断自我完善，还得有吸纳：

```bash
python scripts/method.py ingest <素材路径>
```

先查重，然后两条路——**重复**就比较素材与命中的卡，素材更优则用它改写那张卡，
否则丢掉；**不重复**就直接按格式开新卡。

### 判断不写进脚本

"什么叫更优"、"是否真的重复"都不设规则表。写死的评判标准在遇到没预料过的素材时
必然判错，而这类判断本来就是模型擅长的——脚本只负责把素材和最相近的卡并排摆好
（首位命中给全文，其余给一句话与判据）。

同一条理由也否掉了台账：素材是**过路的**，判完就完，不记「看过没收」。
留下的只有卡本身——要么被改得更好，要么多了一张。
