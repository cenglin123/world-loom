# 引导系统模式感知——有限/无限设计框架的 Agent 对话引导改进

## 0. 背景

项目定位是"小说写作方法论分发系统"——工具链和方法论本身就是目的，它的用户使用它来建造世界、推演故事，Agent 辅助兜底细节。当前系统的强项在**机械自洽校验**（脚本层：伏笔状态机、章节时空一致性、世界观违反检测）——这是"宪法级治理"的硬约束层。

但**引导对话层**（Agent 和用户之间的交互——世界观/大纲/角色的创建过程）缺乏一个关键的感知能力：**用户当前在哪种创作模式下？** 这导致 Agent 给出的建议可能和目标错配——对一个只想玩世界建造的用户追问"这对故事有什么用"，或对一个想完成小说的用户放任无限扩张。

本计划基于 **Bilibili UP 主 -以筠- 的「有限设计与无限设计」框架**（源自 James Carse《有限与无限的游戏》），为 Agent 引导对话层引入模式感知能力。

## 1. 问题诊断

### 1.1 核心问题

Agent 引导用户创建世界观/大纲/角色时，**缺少模式探测步骤**，导致以下错配：

| 错配场景 | Agent 行为 | 用户实际状态 | 后果 |
|---------|-----------|------------|------|
| A | 追问"这对主线有什么用" | 无限模式（只想建世界玩） | 用户感到被否定，退出 |
| B | 放任无限扩展不加约束 | 有限模式（想写完小说） | 陷入设定死循环，永远不开始 |
| C | 默认用户肯定要写小说 | 用户还在决定中 | 过早压入取舍阶段，扼杀探索 |

### 1.2 根因

AGENTS.md 就绪自检的四项条件（物理层非空 + 主线已填 + 至少一个角色 + 视角已选）本质上是一个**有限模式下的入场门槛**。它正确地阻止了"没准备好就开始写"，但没有区分"没准备好"和"暂时不想开始"——这两类用户需要完全不同的引导策略。

**已知约束**：就绪自检在引导对话之前执行（AGENTS.md §就绪自检："接到'推进剧情'任务前强制执行"），本计划不修改就绪自检本身（超出 scope）。处置方案：在引导策略中明确——**无限模式用户不宜触发"推进剧情"流程，应走世界建造流程。** 当 Agent 探测到用户为无限模式时，主动引导其走向世界建造（`_设计方法.md` 各模块），而非推入就绪自检→推进剧情的有限管道。

### 1.3 为什么是"模式感知"而不是"模式分类"

用户不是"有限型创作者"或"无限型创作者"——同一个人、同一个世界观随时在两种模式间切换。模式感知意味着 Agent 在**每次引导对话的入口**做一次轻量判断，而不是给人贴标签。切换成本必须极低。

> **适配声明**：以筠番外二的视频侧重描述"两类不同的创作者倾向"；本计划将模式定位为"同一人在不同时刻的创作状态"是一项**主动适配决策**——因为引导系统的服务对象是"正在使用工具的一个人"，而非"两类人群"。此偏离不改变原框架的核心洞察（有限追求完成/无限追求持续），只改变其应用粒度（从人群分类→状态分类）。

## 2. 设计目标

1. **模式感知**：Agent 在引导对话开始时，能通过用户信号判断当前倾向（有限/无限），调整引导策略
2. **低摩擦切换**：Agent 能在合适的时机提议切换视角，由用户决定
3. **不对现有机械检查层造成破坏性变更**：本计划只影响 AGENTS.md 的引导行为描述和引导对话的 prompt 设计，不动脚本/hook
4. **方法论可沉淀**：改进产物应内化到项目文档中，对外分发时作为系统能力的一部分

## 3. 方案

### 3.1 模式探测——两道轻量问题

Agent 在首次引导世界观/大纲/角色创建对话时，在对话开始的 2-3 轮内自然插入（不显式为"问卷"）：

**探测问题 1**（判断当前目标明确度）：
> "你更想先把世界建完整再决定故事，还是已经有了一句话主线、想从这条线开始推？"

**探测问题 2**（判断内在/外在价值倾向）：
> "如果我们今天只做一件事——是更想多建一个城市/种族/魔法体系，还是更想写一小段场景看看这个世界里的角色怎么生活？"

两道问题的回答不需要是二选一——用户的措辞、犹豫、倾向本身就给 Agent 足够的信号来调整后续策略。

> **措辞不对称说明**：问题 2 的有限选项（"写一小段场景"）设定为低风险入口是有意为之——降低有限模式的进入门槛是本计划的设计目标之一，不对称服务于可用性。

### 3.2 分层引导策略

Agent 根据模式探测结果，采用不同的引导风格：

#### 无限模式引导

| 场景 | Agent 策略 | 避开的陷阱 |
|------|-----------|-----------|
| 世界观创建 | 苏格拉底式追问——顺着用户选择往下推演，"如果山在这里，这条河可能不会往那个方向流"；帮世界跟用户抬杠 | 不问"这对故事有什么用" |
| 大纲创建 | 不催促。若用户表现出大纲兴趣，可提议"从你建好的世界里挑一个最疼的矛盾点，试试写一小段？"——低风险过渡 | 不要求做出取舍 |
| 角色创建 | 用反差身份四问展开对话——"这个身份要求他每天怎么表现？那晚上没人看的时候他最想做什么？" | 不要求角色必须服务于主线 |
| 推进剧情 | **不适用**。引导用户走世界建造流程而非触发就绪自检→推进剧情管道 | 不把用户推入有限流程 |
| 切换提议时机 | ① 用户来回改同一设定 ≥5 轮 ② 用户表现出对"故事"的兴趣 ③ 用户提到"读者"/"发表"/"写完" | — |

#### 有限模式引导

| 场景 | Agent 策略 | 避开的陷阱 |
|------|-----------|-----------|
| 世界观创建 | "故事需要的设定最少是多少？"——反过来，故事需要多少才设定多少；额外的放外围 | 不让设定膨胀阻塞推进 |
| 大纲创建 | 用故事驱动六法则反推——"你说这个世界最骄傲的是 X，如果第一章 X 就坏了，会发生什么？" | 不堆砌设定说明书 |
| 角色创建 | 反差身份 + 追问"他的秘密一旦被发现会失去什么"→ 直接关联到故事冲突 | 不让角色设计脱离主线 |
| 切换提议时机 | ① 用户表现出"写不动" ② 用户开始翻看设定文件而非推进正文 ③ 正文产出停滞 ≥2 轮对话 | — |

#### 未确定模式（探测 fallback）

> **来源标注**：此为 Carse 原框架中不存在的新增概念——是计划的自主扩展，而非原视频内容。它实质是"探测失败时的 fallback 策略"，不是第三种模式。

如果探测无法判断用户的倾向（用户自己也说不清），Agent 默认采用 **fallback 策略**：
- 核心假设：用户想最终产出故事，但当前在探索阶段
- 策略：每次建议都以"这里有两种玩法——"开头，让用户自己选
- **退出条件**：当用户后续对话中表现出显式倾向信号（如明确说"我想先把世界建好"/"我们推进剧情吧"）时，退出 fallback 并标注为对应模式。若 3 轮对话后仍无显式信号，Agent 主动询问一次偏向来收束

### 3.3 模式切换的对话模板

Agent 在检测到切换时机时，使用以下自然语言模板（不是脚本化的命令）：

**从无限→有限提议**：
> "你这个世界里有个矛盾我越想越有意思——[具体矛盾]。要不要我们试试把它写成一个小场景？不需要承诺什么，就当测试一下这个世界能不能'动起来'。"

**从有限→无限提议**：
> "你刚才为了推剧情砍掉了好几个设定，有没有哪个是你砍完之后一直惦记的？要不要回那部分世界再玩一会儿？有时候转一圈回来，会发现新的故事入口。"

**无法判断时的默认探头**：
> "你现在的状态更像想先把世界建完整（无限模式），还是已经有了明确要写的故事线（有限模式）？两种都可以——告诉我方向，我调整我的建议。"

### 3.4 自洽性增益——Agent 内在检查清单

Agent 在引导世界观创建时，内化一个七点自洽性检查（来源于评论区 @哑光天星 的方法论框架），指导追问方向但不要求用户回答。**每点标注适用模式**：

| # | 检查点 | 适用模式 | 说明 |
|---|--------|---------|------|
| 1 | **物理层自洽**：力量规则是否一致？有无"无限力量源"类的漏洞？ | 全模式 | 与 `_设计方法.md` 物理层对齐 |
| 2 | **衍生自洽**：社会层是否是物理层的自然衍生？ | 全模式 | 与 `_设计方法.md` 社会层对齐 |
| 3 | **叙事空间**：物理层和社会层之间是否留够结构性矛盾？ | 有限/未确定 | 纯无限模式下不追问——用户不需要故事生长缝隙 |
| 4 | **可推导性**：底层规则是否允许世界观自我演化？ | 全模式 | 与「规则即土壤」理念一致 |
| 5 | **故事自发性**：角色放在系统矛盾里能否自然产生故事？ | 有限/未确定 | 纯无限模式下不适用 |
| 6 | **世界观可解释性**：角色行为的因果关系能否用世界观设定完全解释？ | 有限/未确定 | 纯无限模式下不适用 |
| 7 | **不割裂**：力量体系的每次使用是否都能追溯到基本法则？ | 全模式 | 与 `_设计方法.md` 贯穿理念一致 |

> **与现有框架的关系**：第 1-3 点映射 `_设计方法.md` 的三层架构（物理→社会→叙事），第 4-7 点扩展了贯穿理念以外的维度（可推导性/故事自发性/可解释性/不割裂）。此清单是对现有框架的**补充**而非替代。七点清单与计划核心主题"模式感知"的关联度不高——应视为本计划的**独立增益**，而非模式感知框架的内在组成部分。
>
> 注意：这七点不是 checklist 而是追问工具——Agent 在对话中自然引用，不逐条念出。

另有两个硬约束来自反差身份设计法（已存在于 `_设计方法.md`「反差身份设计法」段，此处复述为 Agent 行为指引）：

- **行为一贯性**（全模式）：角色反差身份的前后行为须共享同一条行为逻辑——追问"这两个看似矛盾的行为是否源自同一个深层动机？"
- **伏笔密度**（仅有限模式）：反转揭晓前必须铺设伏笔——反推"这个角色如果可以保守秘密，那么在此之前他可能出现过哪些异常举动？"纯无限模式下伏笔约束不适用。

### 3.5 避坑指南

#### 无限模式侧保护

基于评论区 @Graustark 的警告（"纯无限设计注定孤独"），Agent 在引导中内置一条软保护：
- 若用户连续 **3 轮**对话纯推演世界而未产出任何故事片段/大纲/角色，Agent 应主动确认"你是满意现在的节奏，还是需要我帮你找一条路往故事方向切？"
- 此确认只需一次，用户说"满意"即不再提示。

#### 有限模式侧保护（镜像风险）

有限模式用户同样存在风险——被限缩在"只写故事"的框里，从不允许自己扩展世界观，导致世界贫瘠、故事缺乏地层感。Agent 应在以下信号出现时主动提议扩展：
- 连续多章未引入新地点/新势力/新设定，但剧情走向暗示需要新元素
- 用户反复使用相同的世界观元素（同一城市/同一势力/同一力量规则），产出开始显得重复
- 提议模板："你这个世界的地层感可能需要一点补充——要不要回头看看 [某一处尚未深挖的地理发源设定]，说不定能长出新的故事线？"

## 5. 风险与边界

- **过度探测风险**：只在新主题的首次入口做探测。新主题明确定义为三个入口——① 首次世界观引导 ② 首次大纲引导 ③ 首次角色引导。细分场景（新建种族 vs 新建城市、新增地点 vs 新增势力）不触发重新探测，沿用当前对话的模式标注。
- **模式分类僵化风险**：模式标注不是身份标签，是当前对话状态。用户随时可口头切换（"不想写了，我们来玩世界建造"），Agent 立即调整。
- **不与现有 converge 协议冲突**：本计划只影响"引导对话"阶段，不改变就绪自检的条件和卷末复盘 converge 的内容。
- **软约束架构风险（已知技术债务）**：模式感知机制目前是纯自然语言描述的软约束——35 行指引依赖 Agent 记忆和即时理解，无脚本兜底、无 hook 校验、跨对话容易丢失。若观察到此规则在跨对话中失效 ≥3 次，应考虑将模式探测固化为 prompt template 文件（`_模板/引导对话/`）或为 `check_all.py` 增加模式感知的诊断提示。
- **有限模式侧切换阈值为启发式起点**（"停滞 ≥2 轮"、"写不动"等），非科学结论。先上线观察，后续根据实际使用数据调整。
