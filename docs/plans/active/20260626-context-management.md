# 长上下文治理体系 — 实施计划

> 基于方法论报告「应给尽给 vs 长上下文衰减」的两阶段方案。
> 当前无正文内容——正是建立基础设施的最佳时机。

## 目标

在第一次写正文之前，把两阶段上下文管理的基础设施搭好——让 agent 从第一场戏起就走在正确的召回路径上，而不是写到几百条 L2 才发现近因不够用、再回头补基建。

## 实施范围（本次）

### 1. `scripts/recall.py` — 上下文召回 CLI（Phase 1 实现）

```bash
python scripts/recall.py 沈照影 顾寒枝    # 返回在场角色的注入集
                                          # Phase 1: 每人最近 3-5 条 L2 + 所有未解决问题 + 手动 pin
                                          # 输出格式: YAML，可直接嵌入写前上下文包
```

**解析策略**：L2 虽是散文，但有可靠的结构锚点——`#### （场景名）` 切分条目、`**场景**：` / `**我的行动**：` 等字段标签提取值。人物模板的"不可脚本解析"声明将同步修改为"半结构化散文——条目边界和字段标签可机械识别，字段内容为自由文本"。

**Phase 1 行为**：
- 扫描目标角色的 `02_人物/<角色名>.md` 的「二、记忆」段
- 按 `####` 标题切分 L2 条目，按 `**字段**：` 标签提取值（时间倒序）
- 过滤：取最近 5 条 + 所有 `[pinned]` 标记的条目 + 所有"未解决的问题"非空的条目
- 去重后输出 YAML，每条含：场景名、我的判断、未解决问题、情感轨迹摘要。L1 元记忆单列在最前
- **YAML 是 agent 的内部材料**——agent 读取后将其转写为自然语言注入 `_准备_第M章.md`，不直接粘贴 YAML 到上下文包

**Phase 2 预留**：
- `--mode embedding` 参数位（当前接受但 fallback 到 Phase 1 行为）
- 当 embedding 模型可用时，用相关性排序替代纯时间序
- L2 计数命令：`recall.py --count` 统计全仓库 L2 条数，作为 Phase 2 触发定量的数据源

### 2. L2 记忆增加 `pinned` 字段（Phase 1.5 过渡机制）

在 `02_人物/人物模板.md` 的 L2 记忆格式中增加可选标记：

```markdown
#### （场景名）  `[pinned]`
```

`[pinned]` 表示此记忆为"跨卷相关"——即使远超近因窗口，`recall.py` 仍将其注入。agent 或用户在复盘时手动添加此标记。

### 3. L2 计数追踪

在 `scripts/check_chapters.py` 或独立脚本中加入 L2 计数统计，输出仓库总 L2 条数。作为 Phase 2 触发定量的数据源。

### 4. AGENTS.md 更新

§② 写前准备的步骤重写为精确顺序：

1. 确定在场角色列表
2. `python scripts/recall.py <角色1> <角色2>` → 获取注入集 YAML
3. `python scripts/relationship.py show <角色名>` → 获取关系摘要
4. agent 将 recall.py 的 YAML 转写为自然语言，与关系摘要、本场大纲、场景初始状态组装为上下文包（~300-500 字自然语言），写入 `_准备_第M章.md`

完工检查清单增加 `[pinned]` 标记检查项。

### 5. reviewer 协议更新

- `05_复盘/reviewer-protocol.md` 的硬阻断项增加"角色遗忘早期事件"（L2 记忆中已有的事实被后续剧情矛盾）
- 这是 Phase 2 触发的定性信号
