# 20260818-卷级审计分维降本

> 背景：2026-08-18 的 token 消耗分析结论——卷末 converge（§④）是全流程最大开销：全卷正文 × 最多 5 轮 fresh reviewer。本计划把审理素材改为「首轮全量、续轮增量」，收敛标准（零硬阻断、轮数上限、振荡硬停）不动。
> 属治理协议改动——按仓规，执行前走 converge 评议。已经两轮评议（round-1：4 硬阻断 4 软阻断；round-2：3 硬阻断 3 软阻断），修订点：场景清单存在性设为执行前提、例外清单改「至少包含」+不确定恢复全量、增量正文改连续区间、模板改使用说明区补句（代码块不动）、扩读条款、风险判定时机与落盘、影子轮时机与比对口径。

## 变更清单

### 1. 审理素材分轮注入

**目标文件**（成对同步）：`05_复盘/reviewer-protocol.md` ↔ `_模板/05_复盘/reviewer-protocol.md`

**改动**：

(a) 节标题「审理素材（每次 reviewer 必须全量注入）」→「审理素材（首轮全量、续轮增量）」

(b) 现行清单 1-8 保持不动，作为**第 1 轮全量注入**的清单

(c) 清单之后新增「续轮注入」小节：

- **固定注入（每轮全量）**：现行清单除正文（第 1 项）外的全部判据/基线/索引/上下文包项（世界观核心+外围、主线、涉及角色人物卡、伏笔登记表、本卷全部上下文包、style-locked/writing-style/audit-checklist、文风样本若登记）+ 卷级场景清单（`第N卷_大纲.md` 或 `01_大纲/主线.md` 分卷节内的场景清单表）+ 上一轮 reviewer 原始 YAML 报告
- **增量注入（唯一增量部分是正文）**：**连续区间**——自最早修复章的前邻章至最晚修复章的后邻章（含端点）；单章修复 = 该章 ±1 章
- **扩读**：续轮 reviewer 怀疑注入集之外存在矛盾时，不自行扩读，在输出 flags 声明「需扩读：<文件/章>」；Orchestrator 在下一轮把扩读项并入注入清单（轮数照常计）
- **例外（恢复全量正文）**：executor 修复完成后、下一轮 spawn 前，Orchestrator 依据 executor 的**修复声明**（改了哪些阻断、触及哪些章/设定）做风险判定；触发清单**至少包含**以下情形——修复触及场景顺序/时间戳、显式跨章引用（角色/事件/物件在他章的提及）、共享规则/数值/角色状态的改动、修复章区间跨度 ≥3 章（首尾含端点）；判定为「不确定」时一律恢复全量。判定结论连同理由写入该轮 round-N 记录

**执行前提**：进入 §④ 时卷级场景清单必须存在——`check_maintenance.py` 本就把「场景清单 ↔ 已写章节」对齐列为卷末维护待办；缺失时先按 [[01_大纲/README]] 第四级补齐，再开始复盘。

**理由**：token 大头是正文全量重传——判据/基线/索引/上下文包体积小，固定全量保证全部现行硬阻断类别与软阻断维度（文风漂移/达成断言兑现）在续轮仍可判定；跨章风险由「场景清单 + 伏笔表/记忆段等判据全集 + 连续区间正文 + 风险判定兜底」覆盖。

### 2. reviewer 模板同步

**目标文件**（成对同步）：`05_复盘/reviewer-prompt-template.md` ↔ `_模板/05_复盘/reviewer-prompt-template.md`

**改动**：**代码块内「必读材料」不动**；在代码块外的「使用说明」区补一句——§④ 卷级复盘按 reviewer-protocol「审理素材」清单注入（首轮全量、续轮固定全集+增量正文）；§③ 单场写后审沿用代码块内 6 项最小集。注入清单以协议为单一源，模板不复制清单。

### 3. workflow.md §④ 措辞同步

**目标文件**：`docs/workflow.md`

**改动**：§④「spawn reviewer → 全量审计 → executor 修复」→「spawn reviewer → 首轮全量、续轮增量审计 → executor 修复」，协议细节仍指向 [[05_复盘/reviewer-protocol]]。

> `docs/workflow.md` 不在 `.githooks/commit-msg` 治理清单——该同步点无 hook 兜底，靠本计划自觉（同批提交，`[governance]` 标记由 protocol 两对文件触发）。

### 4. 观测与回滚

**观测（可证伪 oracle）**：第一卷**收敛达成后、L2 记忆回写（协议步骤 6）之前**，加跑一轮影子全量轮（仅第一卷、仅一次）——同一 reviewer 协议、正文全量注入，判据文件状态与增量轮一致。比对基准 = **收敛轮（最后一轮增量轮）的检出集**：影子轮检出 ≥1 条收敛轮未检出的硬阻断 → 判定例外条款不足 → 回滚全量注入。影子轮产出按正常 round-N 落盘，检出的硬阻断走正常修复流程。

**回滚 = 全部改动点逐一 revert**：§1 节标题与续轮小节、§2 使用说明补句、§3 workflow 措辞。不涉及脚本与数据格式，无迁移成本。

## 治理影响

`05_复盘/reviewer-protocol.md`、`05_复盘/reviewer-prompt-template.md` 及其 `_模板/` 成对文件在 `.githooks/commit-msg` 治理清单 → `[governance]` 提交；`docs/workflow.md` 不在清单，同批提交由前者触发标记。

## 明确不做

- 不动第 1 轮全量注入（质量锚点）
- 不动阻断分类、收束标准、轮数上限、振荡硬停
- 不动 §③ 写后审（模板代码块不动，补句在代码块外）
- 不引入新索引制品（如时间线快照）——跨章锚点用场景清单（执行前提保证）+ 判据全集 + 风险判定
- 不把轮数分流做进脚本——由 Orchestrator 判断（机制化三分判据：语义判断不硬编码）
