# 计划

> 跨卷/多角色/跨文件的任务在这里落盘。三个状态目录，计划随进展在其间移动。

| 目录 | 含义 | 何时移入 |
|------|------|---------|
| `active/` | 进行中 | 开始动手时 |
| `completed/` | 已完成 | 落地并验证后 |
| `deferred/` | 已搁置 | 阻塞条件明确、当前做不了时 |

## 搁置中的计划

> **deferred 不是垃圾桶——是有解锁条件的待办。** 每条都写明什么条件满足后可以启动，
> 否则它们会变成没人记得的隐形 backlog。卷末复盘时过一遍这张表。

| 计划 | 解锁条件 |
|------|---------|
| [[docs/plans/deferred/20260731-中段推进方法论\|中段推进方法论]] | 完成第一卷，有真实中段体验 |
| [[docs/plans/deferred/20260728-8篇论文改进方案-去重提取\|8 篇论文改进方案]] | 第一卷复盘 converge 通过 |
| [[docs/plans/deferred/memory-retrieval\|记忆检索升级]] | L2 累积到数百条，近因召回开始漏 |
| [[docs/plans/deferred/20260628-角色扮演功能-边界厘清与推进路线\|角色扮演功能]] | 至少完成一卷正文 |

四条都卡在同一个前提上——**得先真的写出内容**。这不是巧合：它们全是"用起来才知道该怎么调"的东西，现在硬做等于凭空猜参数。

## 归档

`completed/` 与 `deferred/` 是**档案**，不需要被其他文档引用——但 deferred 必须在上表可见，否则等于丢失。
