## 1. L2 遗忘机制（MemoryBank）

### 论文来源

MemoryBank（Zhong et al., 2023）首次将艾宾浩斯遗忘曲线引入 Agent 长期记忆。核心公式：

```
R = e^(-t/S)
```

- R：记忆保留率
- t：自上次访问的时间
- S：记忆强度（整数，每次回忆 +1，t 重置为 0）

效果：常被回忆的记忆永不遗忘；从未被访问的记忆自然衰减淘汰。

### 当前项目缺口

L2 情节记忆是纯追加模式——只增不减，靠"未解决的问题闭合后自然老化"做被动清理。这在 L2 条目少时没问题，但 ~数百条之后会出现：
- 角色"记得太多"——五卷前的过场信息仍被注入
- 未解决问题闭合后的条目仍在占位
- 无机制区分"卷 1 的核心创伤"和"卷 1 的某顿早饭"

memory-retrieval 计划解决的是**检索**（选哪些进上下文），遗忘机制解决的是**存储卫生**（哪些值得保留）——两者正交。

### 方案概要

为每条 L2 条目维护两个隐式字段（不入正文，脚本计算）：

| 字段 | 含义 | 初始值 |
|------|------|--------|
| `access_count` | 被 recall.py 召回的次数 | 0 |
| `last_access` | 最后一次被召回的场景时间戳 | 创建时间 |

场景结束后运行 `scripts/forget.py`（新脚本）：
1. 对每条 L2 计算 `R = e^(-Δt / (access_count + 1))`
2. R 低于阈值的条目 → 标记 `archived`（不删除，移出活跃 L2）
3. 触及内核四维的条目 → 永久豁免（`pinned`）

**设计原则**：遗忘是归档不是删除——和 L2 可修订纪律（F3，追加不覆盖旧条目）一致。被归档的条目仍存在于角色文件，只是不再注入上下文。若后续剧情需要（角色翻旧账），可显式召回。

### 触发阈值

L2 条目累计 **≥ 200 条**（约 2-3 卷后）。此前的纯近因召回 + 未解决问题挂起足够。

### 与 memory-retrieval 的关系

```
L2 存储卫生（本计划 §1）  →  淘汰/归档低价值条目
        ↓
L2 检索（memory-retrieval）→  从剩余条目中选相关者进上下文
```

先做遗忘再做检索——减少检索候选集，降低 RAG 噪音。两个计划合并执行时机：L2 ~数百条时，遗忘 + RAG 一起上。

## 2. 记忆污染守卫（Generative Agents §局限）

### 论文来源

Generative Agents 明确记录：Agent 可能从语言模型继承"虚拟知识"造成记忆污染——如把邻居 Adam Smith 当作《国富论》作者。当 LLM 的世界知识侵入 Agent 的个人记忆时，无法隔离。

### 当前项目缺口

对小说写作而言，这是比社会模拟更严重的风险：
- 写作 agent 的预训练数据包含地球的历史、物理、文化、社会规范
- 虚构世界可能有完全不同的物理法则、历史事件、社会结构
- Agent 在写角色 L2 回写或生成正文时，可能无意识地引入现实世界常识——角色"记得"了虚构世界里不存在的东西

当前的 converge 审查检查的是"是否违反核心设定"，依赖 reviewer 的语义判断。但 reviewer 本身也是 LLM，同样有记忆污染风险——它可能看不出"角色下意识认为太阳从东边升起"在虚构世界（如天圆地方、双太阳）中是错误的。

### 方案概要

**不另建独立检查层**（Occam——已有 converge reviewer，不加新审查者）。而是在复盘 converge 的 reviewer prompt 中追加一条检查维度：

```
记忆污染检查：逐条核对本章新增的 L2 回写，是否存在以下污染——
  (a) 引用了现实世界特有实体（国家名、历史事件、科技产品、名人）
  (b) 依赖了现实世界物理/社会默认值（除非核心设定明确保留该默认值）
  (c) 角色的常识判断基于 LLM 训练数据的统计规律而非本世界设定
发现污染 → flag（soft_block），修复方式：删除污染条目或替换为世界观内等价物。
```

**为什么不做脚本化**：记忆污染是语义问题——"太阳从东边升起"在默认世界不是污染，在天圆地方世界就是。需要语义判断，不能硬编码规则（Bitter Lesson）。

### 触发阈值

第一卷写完后首次复盘 converge 时启用。零成本（只是在 reviewer prompt 中加一段），无新依赖。

## 3. 写作经验蒸馏（Reflexion）

### 论文来源

Reflexion（Shinn et al., 2023）的核心创新：Agent 不改模型权重，而是将失败经验写成文字反馈，存入 episodic memory，下一轮任务再利用。这被称为**口头强化学习**——梯度信号被文本化的经验总结替代。

### 当前项目缺口

现有 converge 复盘检查的是 **"输出有没有错"**（违反世界观/人设漂移/伏笔悬空/时间线倒流）。Reflexion 提供的是另一条轴：**"怎么做下次更好"**。

converge reviewer 在审计中发现的问题（如"对话标签过多""场景转换生硬"）目前作为 flag 记录后即丢弃——不会形成可被后续写作 agent 读取的积累经验。

### 方案概要

在复盘 converge 的收尾阶段追加一步：

1. 复盘 reviewer 在完成一致性审计后，额外输出 **≤3 条"本卷写作经验"**
2. 格式：`经验：[具体问题] → [改进方向] → [本卷中的实例]`
3. 存入 `docs/writing-craft.md`（新文件），按卷归类，不覆盖旧条目
4. 后续写作时，`recall.py` 的上下文包注入附带最近 3 条相关经验

**与 converge flag 的区别**：

| | converge flag | 写作经验 |
|---|---|---|
| 回答的问题 | 这里有没有错？ | 下次怎么写得更好？ |
| 处理方式 | 阻断/修复 | 记录/注入 |
| 生命周期 | 修复后关闭 | 持续积累，永不删除 |
| 例子 | "角色 A 在 ch3 已死，ch7 又出场" | "本卷动作场景的动词重复率高，下次用身体部位+动词组合替代" |

### 触发阈值

第一卷复盘 converge 通过后启用。零新依赖——复用现有 reviewer。

### 风险

经验条目随时间积累可能膨胀。对策：经验也走 Ebbinghaus 遗忘——若某条经验在后续 N 卷中未被 reviewer 再次提及（即问题未复发），降低其注入优先级。具体衰减参数待 §1 的 `forget.py` 就绪后复用同一框架。

## 4. 场景模式库（Voyager）

### 论文来源

Voyager（Wang et al., 2023）的核心创新是**技能库（Skill Library）**——将每个成功掌握的任务存储为可执行函数，形成程序性记忆。关键属性：与上下文无关（任何场景可用）、天然可组合（新技能调用旧技能）、永不遗忘（成功即永久入库）、可移植（跨 Agent 复用）。

### 当前项目缺口

`_模板/` 提供的是空白骨架（人物卡模板、章节模板）——写之前的结构。Voyager 思路是反过来的：从**已写的内容**中提炼已验证有效的模式，作为"这个模式在本书中好用"的经验资产。

例如：写了三场对峙戏后，可能浮现一个模式——"先展示力量差距 → 用环境细节暗示转机 → 弱势方言辞上的小胜作为 hook"——这个模式不是模板规定的，是从实际写作中涌现的。

### 方案概要

**最远期、最不紧迫。** 仅在 §3 写作经验蒸馏稳定运转 ≥2 卷后，若出现以下信号才考虑：

- 同类场景（对峙/揭秘/告别/初遇）被多次写作且 reviewer 反复标记同类问题
- 或 reviewer 反复肯定某类场景的处理方式

届时做法：
1. 从写作经验中抽取"场景类型 → 已验证有效结构"的映射
2. 存储为 `docs/scene-patterns.md`（散文描述，非可执行代码——Voyager 的技能是可执行 JS，小说场景模式是结构描述）
3. 写作 agent 在准备同类场景时注入对应的模式参考

**注意**：与故事驱动法则（`docs/writing-style.md`）的关系——驱动法则是**通用技法**（适用于任何小说），场景模式库是**本书特化**（这个具体故事里什么好用）。不替代，是补充。

### 触发阈值

§3 写作经验蒸馏稳定运转 ≥2 卷 + 经验条目 ≥ 30 条。在此之前不建——过早的模式提取会从不足样本中过度泛化，反而约束写作。
