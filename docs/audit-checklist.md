# 一致性审计清单

> 先跑机械检查，再按本清单逐项人工裁决——**机械层通过 ≠ 语义一致**。

## 机械检查项

- [ ] `python scripts/check_all.py` 全绿。检查器清单以脚本内 `CHECKS` 为准（同步 / 模板层 / 死链 / 伏笔 / 关系 / 标签 / 章节时空 + 就绪自检），本文不重复枚举以免漂移。
- [ ] AGENTS.md 行数在 200 行以内、词数在 400 以内：`python scripts/audit.py check` 含行数/词数检查

## 小说专项审计（agent 手动裁决）

### 世界观一致性（以硬阻断为主——违反物理层即阻断）
- [ ] `00_世界观/核心设定.md` frontmatter `locked: true` 的物理层未被绕过多轮独立评审修改（改动须带 `[governance]` 提交标记）
- [ ] 硬核心设定里的数值/地名/法则在近期正文中无违反
- [ ] 外围设定的增量补充未与硬核心冲突

### 人设一致性（混合——事实层硬阻断，动机解释层软判断）
- [ ] 角色行动可由其当前信念、本场目标、核心价值排序、默认策略/压力退化模式和认知盲点解释；不能只用“冷静/冲动”等标签圆场
- [ ] 角色越过行为边界时，正文已满足人物卡所列越线条件，并兑现相应代价
- [ ] 有演化的角色：人物卡「演化记录」已追加触发事件、付出代价、旧状态与新状态；演化前后因果自洽且未覆盖历史
- [ ] 角色的对话/叙述与其 `style_register` 对应的文风注册一致——未出现注册中“禁用”的词汇/句式（参照 `docs/style-locked.md` 文风注册表）
- [ ] **对话独特性**：遮住对话标签和人名后仍能分辨谁在说话（词汇范围/句长节奏/回避什么/先注意到什么；口头禅是最弱的区分手段）
- [ ] **演化可追溯**：有演化的角色，其演化能追溯到某个被动场景的「决定」——不是凭空转变

### 记忆一致性（以硬阻断为主——矛盾条目客观可判定）
- [ ] 所有在场角色的 `<角色名>.md` 记忆段的 L2 条目已在当前卷结束后更新
- [ ] 每条新 L2 是主观视角格式（场景/我的行动/我的判断/情感轨迹/未解决问题/对他人看法变化）
- [ ] 无角色持有矛盾的 L2（两条记录对同一事实给出不同判断但无演化说明）

### 关系一致性（混合——格式硬阻断，更新必要性软判断）
- [ ] `02_人物/_索引.md` 中的关系矩阵与各角色 `<角色名>.md` 关系段一致
- [ ] 近期有互动的角色对，其四格（公开/隐藏/盲区/禁区）已检查是否需要更新

### 伏笔一致性（混合——超期硬阻断，回收合理性软判断）
- [ ] `04_伏笔/伏笔登记表.md` 中所有 状态=open 的伏笔未超期（未收超过 N 卷）
- [ ] 已收伏笔的回收方式与登记表中的预期一致（不一致但合理的记录理由）

### 时间线一致性（以硬阻断为主——倒流/同时两地客观可判定）
- [ ] 事件顺序无倒流（有时间戳的事件可机械校验；模糊时序的事件靠语义判断）
- [ ] 无角色在同一时间段出现在两个不同地点（除非世界观允许）

### 开篇结构（以软判断为主——部分字数/位置可机械验证）
- [ ] 前三章已强化主角存在感（未在开篇大段堆世界观设定）
- [ ] 首章 300 字内主角已出场、首个冲突已抛出
- [ ] 三万字内第一个主要矛盾已解决（`03_正文/第1卷/` 下章节总字数 ≤ 30000 时首个矛盾必须闭合）

### 简介一致性（以软判断为主——卷末复核）
- [ ] `简介.md` 的一句话与 `01_大纲/主线.md` 的主线不矛盾
- [ ] 简介描述的开局情境与已写正文一致（人物身份、初始处境、抛出的第一个冲突）
- [ ] 简介许诺的核心张力，在已写部分有兑现或正在铺垫——没有变成"说好写 A 结果写了 B"
- [ ] 「当前进度」段与实际写到的卷/章一致
- [ ] **若故事已偏离简介**：判定是**有意演化**（故事长出了更好的方向 → 更新简介）还是**无意漂移**（写着写着跑题 → 回看该收回来还是接受新方向）。两者都合法，但必须是**判断过的**，不是没注意到

### 结构与工具（观察项——不阻断）
- [ ] `docs/CURRENT.md` 与实际任务状态一致
- [ ] `docs/plans/active/` 无僵尸计划（超过 30 天未更新）
- [ ] CHANGELOG 无格式异常
- [ ] **指令类文档无补丁感**——AGENTS.md、`docs/` 方法文档、各目录 README、`_模板/` 骨架、人物模板、`05_复盘/` 协议文件读起来是一套自洽规则，而非逐层叠加的修订史。两种形态都要查：
  - **字面**：是否残留"原为…现改为…""v2 新增""不再使用…"类演进注记
  - **结构**：新增内容是否融入了既有序列——编号连续、总数措辞（"以下六种…"）与实际项数一致、没有把后加的部分用分隔线隔在末尾或开头
  - 例外：CHANGELOG、`docs/plans/`、`05_复盘/` 的 converge 记录本职即记录变化，不适用本条
  - 不脚本化：字面形态可正则粗筛但误报高（正文用语可能合法命中），结构形态正则完全看不见——按 Bitter Lesson，交 LLM 判断
