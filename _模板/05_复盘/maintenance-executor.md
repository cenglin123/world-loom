# 维护子代理协议

> 章节写完、审稿通过之后的**回写工作**——记忆、关系、演化、伏笔——由维护子代理执行，不占用主对话 agent 的注意力。
> 与 [[05_复盘/reviewer-protocol]] 并列：一个审、一个修，都是写完之后派出去的独立 agent。

## 为什么要派出去

主对话 agent 的注意力应该在创作判断和与用户的对话上。回写工作**规格确定、验收确定**——属于机械执行，不需要旗舰级判断力。

主 agent 在这条链路上只剩两个动作：

1. **派发**——把 `check_maintenance.py` 输出的待办清单转成子代理的自足 prompt
2. **验收**——确定性检查文件是否真的被改了，不采信子代理的自我报告

## 触发时机

| 时机 | 范围 | 通道 |
|------|------|------|
| 单章审稿通过后 | 该章在场角色 | 框架原生子代理 |
| 卷末复盘时 | 全卷所有角色 | 框架原生子代理（可并行，每角色一个） |

**先跑 `python scripts/check_maintenance.py --chapter <路径>` 拿到待办清单**，再据此派发。没有待办就不派——不要为了流程完整而空跑。

## 自足 prompt 模板

子代理是**全新上下文**：它没有你和用户的对话历史、不知道这本书写到哪、不知道哪些文件不能碰。**它会自信地用错误的先验补齐缺失信息。** 所以下面六项一项都不能省。

```text
【任务】
把第 <N> 卷第 <M> 章的剧情结果回写到人物与关系数据。
完成标准：下方【输出】列出的每个文件都已实际修改，且符合【格式】的 schema。

【输入】只读以下文件：
- <绝对路径>/03_正文/第N卷/第M章.md            （本章正文）
- <绝对路径>/03_正文/第N卷/_准备_第M章.md      （写前上下文包，含场景决策）
- <绝对路径>/03_正文/第N卷/_审查后_第M章.md    （审稿结论，若存在）
- <绝对路径>/02_人物/<角色1>.md                （待回写的人物卡）
- <绝对路径>/02_人物/<角色2>.md
- <绝对路径>/docs/frontmatter-schemas.md       （字段定义权威源）
禁止读取上述之外的任何位置。

【输出】按下列清单修改文件：
1. 02_人物/<角色1>.md —— 「二、记忆」段追加一条 L2
2. 02_人物/<角色2>.md —— 同上
3. 关系更新执行：python scripts/relationship.py update <角色1> <角色2> --trigger "<本章事件>"
4. （若适用）演化记录追加：见【格式】第三节

不要新建文件。不要修改正文、准备包、审稿结论。

【格式】
一、L2 记忆条目（追加到「二、记忆 / L2 · 情节记忆」段末）
#### <场景名>
- **我的行动**：
- **我的判断**：
- **情感轨迹**：
- **未解决的问题**：
- **对他人看法的变化**：

要点：L2 是**主观记忆**，不是客观剧情摘要。同一事件在不同角色心里应留下不同判断——
角色只知道自己感知到的部分，不知道作者掌握的全貌。

二、关系更新
用 relationship.py 的四格模型（公开 / 隐藏 / 盲区 / 禁区），--trigger 写本章的具体事件。

三、演化记录（仅当本章确实改变了角色的「当前稳定内核」或「身份矛盾」字段时）
在「演化记录」表追加一行：生效时间 / 触发事件 / 付出代价 / 旧状态 / 新状态 / 影响字段。
**禁止覆盖已有行。**
判据：写前准备包的「被动场景·决定」是否导致价值排序、自我认同、默认策略、
行为边界、表面身份、秘密自我之一发生了实质改变？没有就不要追加——
无触发的改变是漂移，比不记更糟。

【边界与禁区】
- 禁止修改 03_正文/ 下任何文件
- 禁止改写演化记录的历史行，只能追加
- 禁止发明本章正文里没有的事件、对话或心理活动
- 对无法从正文确定的信息：保留空白并标记 [UNCERTAIN]，禁止基于常理猜测补全
- 本书的世界观硬设定在 00_世界观/核心设定.md，若回写内容与之冲突，停下并报告，不要自行调和

【执行证据】返回中必须包含：
- 实际修改的文件完整路径列表
- 每个文件新增的行数
- 若跳过了某项（如判定无演化），说明判定理由
未实际修改文件的报告视为执行失败。
```

## 验收清单

主 agent 收到"完成"信号后**逐项确定性验证**，不采信自我报告：

- [ ] 待办清单里的每个人物卡**确实被修改**（`git diff --stat 02_人物/`）
- [ ] 新增的 L2 条目字段齐全（场景 / 行动 / 判断 / 情感轨迹 / 未解决问题 / 看法变化）
- [ ] 演化记录若有追加：**旧行未被改动**（`git diff` 只应有增行）
- [ ] `python scripts/check_maintenance.py --chapter <路径>` 现在通过
- [ ] `python scripts/check_all.py --quiet` 无输出

**验收失败的处理**：把失败原因写进新 prompt 的【边界与禁区】作为额外约束重派，不要自己动手补。典型追加约束：

> 上次执行声称完成但未产出任何修改——本次必须实际写入文件，并在回复中列出每个文件的新增行数。

同一章最多重派 2 次。仍失败则主 agent 接手并记录原因——可能是任务描述本身有歧义。

## 与其他机制的关系

| 机制 | 管什么 | 关系 |
|------|--------|------|
| `check_maintenance.py` | 检测**该做什么** | 本协议的输入 |
| `.githooks/pre-commit` | 提交时提醒**还没做** | 兜底，防止漏派 |
| 维护子代理（本协议） | **实际执行**回写 | — |
| [[05_复盘/reviewer-protocol]] | 卷末**语义审计** | 兜底，查回写质量 |

四层各司其职：脚本发现、hook 提醒、子代理执行、复盘审查。主 agent 只在派发和验收两个点上介入。
