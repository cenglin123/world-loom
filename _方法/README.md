# 方法卡库

一张卡 = 一套可照做的步骤。**不常驻上下文**——按需检索、按需展开。

```bash
python scripts/method.py find "不知道该写什么了"   # 不知道用哪张就先搜
python scripts/method.py show 长篇失速诊断         # 展开整卡
python scripts/method.py index --stage 世界观      # 只看某阶段的路由表
```

`_索引.md` 由脚本生成，是常驻的那一层：每卡一行（一句话 + tags）。
卡再多，常驻开销也只随卡数线性涨一点点；真正的正文只在命中时才进上下文。

## 卡片格式

```yaml
---
id: 组织建制法          # 唯一，等于文件名
阶段: 世界观             # 世界观 / 人物 / 大纲 / 正文 / 复盘
tags: [社会层, 组织]     # 归类
关键词: [学院, 门派]     # 术语——作者会怎么称呼它
症状: [组织内部没有矛盾]  # 原话——**求助者**会怎么描述这个问题
一句话: ...              # 进索引的那一行，必须自带判断力
落点: 00_世界观/...      # 产出写到哪个文件
相关: [城镇选址评分法]    # 双链，find --hop 1 会带出来
来源: [星白Knut/如何...] # 若这张卡来自外部素材（内部下沉的可省）
---
```

正文两节：**步骤**（编号，可照做）和**判据**（怎么算做完了）；
被素材修正过的卡末尾另有 **`## 沿革`**。

`症状` 是检索能不能用起来的关键。作者写卡用术语（"派系裂痕"），求助的人说的是
"组织内部没有矛盾"——词面检索跨不过这道鸿沟，只能靠写卡时把两套词都写进去。
缺这一栏 `method.py check` 会拦。

## 收录判据

**只收方法，不收素材。** 方法是"怎么做"，素材是"有什么"。
奇幻生物图鉴、骑士盘点、占卜方式一类的资料不进库——模型本身就知道一大堆，
收进来既重复又永远收不完，还会把索引撑坏。方法论才是稀缺的、模型不会主动照做的东西。

**常驻的判据不进库。** 像「故事驱动法则」这种任何时候都成立的短判据，留在
`docs/writing-style.md` 常驻。路由的意义在于筛掉当前用不上的东西——
永远用得上的东西没有筛的必要。

## 吸纳素材

```bash
python scripts/method.py ingest <素材文件或目录>
```

生成**加工工单**：每份素材配上库里最相关的三张卡（含它们现有的判据），
再逼你回答三问。脚本不做蒸馏、不判收不收——它只把对比材料摆到位并把问题问出来。

### 三问

**一、有可照做的步骤吗？** 没有就不是方法，别开卡。

**二、它和这几张卡的判据冲突吗？** ——**这一问不许跳过。**

素材和已有卡重复，不等于它没价值。恰恰相反，最有价值的素材往往正是那些
"库里好像已经有了"的——它们要么补一个新外壳，要么多一条新步骤，
要么直接**推翻**某条判据。只做单向查重（"库里有没有"）会把这类反馈全部丢掉。

| 判断 | 处置 |
|------|------|
| 冲突 | 改那张卡，并在其 `## 沿革` 记一行：改了什么、依据哪份素材 |
| 不冲突但补强 | 并进那张卡；新外壳写进 `关键词`，新说法写进 `症状` |
| 同一套步骤换外壳（建城邦 vs 建国家 vs 建学院） | 并卡，别开新的 |
| 落点与判据都不同 | 开新卡，写 `来源:`，与最近的卡互相 `相关:` |

拿不准就看**落点**——落点相同的基本是同一张卡。

**三、处置留痕了吗？** 开卡的写 `来源:`；没开卡的登记：

```bash
python scripts/method.py skip "<频道/标题>" --reason "<为什么不成卡>" --revised "<被它改过的卡>"
```

`--revised` 是关键：**不收 ≠ 无影响**。一份没有可照做步骤的素材，
完全可能推翻某张卡的判据。把这两件事记成一件，等于把最有价值的那类反馈丢了。

登记过的来源，`ingest` 下次自动跳过——不重复评估同一份素材。

### 沿革

卡被素材修正后，在末尾 `## 沿革` 追加一行。**正文只描述当前规则**（无补丁感），
演进痕迹另存——和人物卡「演化记录」与当前人设分开是同一条规矩。
`沿革` 不参与检索，改得多的卡不会因此更容易被命中。

### 收完

```bash
python scripts/method.py index && python scripts/method.py check
```

check 会用 BM25 反查全库拦近重复，并核对台账里声称修正过的卡确实存在。
