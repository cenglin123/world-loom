# 复盘 converge 本地协议

> 本文件是 converge 迭代收敛在本仓库的最小可行实现——不依赖外部 SKILL。reviewer 每次以**新 agent 实例**（fresh context）启动，只注入审查素材，不含历史对话。

## 角色

| 角色 | 担任 | 关键约束 |
|------|------|---------|
| **Orchestrator** | 主对话 agent | 管理循环 + 语义判定；不兼任 reviewer |
| **Reviewer** | 每轮新 spawn 的独立 agent | 全新上下文，只读审查素材 |
| **Executor** | 主对话 agent（或新 spawn） | 对照阻断清单逐项修复 |

## 审理素材（每次 reviewer 必须全量注入）

1. 本卷全部正文（`03_正文/第N卷/*.md`）
2. `00_世界观/核心设定.md` + `00_世界观/外围设定.md`
3. `01_大纲/主线.md`
4. 所有涉及角色的 `02_人物/<角色名>.md`
5. `04_伏笔/伏笔登记表.md`
6. 本卷每场的上下文包（`03_正文/第N卷/_准备_*.md`）——用于判读达成断言是否兑现
7. `docs/style-locked.md`（视角/时态/文风注册表，漂移基线）+ `docs/writing-style.md`（技法 rubric）+ `docs/audit-checklist.md`（小说专项审计项）

## 阻断分类

| 级别 | 判据 | 处置 | 示例 |
|------|------|------|------|
| **硬阻断** | 可客观判定的事实错误 | 必须修，不计入"可接受" | 世界观违反/人设内核违反/伏笔悬空/时间线倒流/数值矛盾/角色遗忘早期事件（L2 已记录的事实被后续剧情矛盾） |
| **软阻断** | 需审美判断的问题 | reviewer 指出 → 用户裁决是否接受 | 节奏拖沓/对话生硬/情感张力不足/文风不一致 |
| **flag** | 提示级，不阻断 | 记录，累计观察 | 某角色连续 N 章无内心描写/某场景缺乏感官细节 |

## 收束标准

- **零硬阻断** = 可收敛（软阻断经用户确认可接受即可）
- 同一硬阻断源出现 ≥3 次 → **振荡硬停**，向用户报告："此问题在多轮审查中反复出现且无法根除，可能是设定或大纲层面的方向性缺陷，需要重新设计而非修补"
- **最多 5 轮外循环**，超限 → 停止，呈现用户决策菜单：续审 / 接受当前 / 简化范围

## reviewer 输出格式

```yaml
round: N
verdict: <可收敛 | 需修复 | 需重新设计>
hard_blocks:
  - id: H1
    description: "<具体描述>"
    attribution: <world_defect | outline_defect | character_drift | writer_error>
    location: "<章节/文件>"
    fix_direction: "<修复建议>"
soft_blocks:
  - id: S1
    description: "<具体描述>"
flags:
  - id: F1
    description: "<观察项>"
```

## Orchestrator 流程

0. **收到 reviewer 输出后立即落盘**：reviewer 的原始 YAML 审计报告写入 `05_复盘/<日期>-<主题>-round-N.md`，不管 verdict 是什么。这是硬约束——reviewer 是独立上下文 spawn 的，它的输出不在主对话的任何对话记录里；不落盘 = 唯一的原始审计内容丢失。
1. 收集审理素材 → spawn reviewer（新 agent 实例）
2. 若 verdict = 可收敛 → 收敛完成，写复盘记录
3. 若 verdict = 需修复 → executor 逐项修 → spawn 新 reviewer 二审 → 反复到收敛或超限
4. 若 verdict = 需重新设计 → 停止循环，向用户报告方向性缺陷
5. 振荡检测：每轮记录阻断源 → 同源 ≥3 次 = 硬停
6. 复盘完成后，更新受影响角色的 L2 记忆 / 关系 / 人设，写入 `05_复盘/第N卷_复盘.md`

## 小说章节 vs 非小说 converge

本协议最初为小说章节复盘设计（审理素材 = 正文/人物卡/伏笔表），但 converge 的场景不止于此——治理文档修改、跨仓库 plan 审计、脚本重构等同样需要独立 reviewer + 迭代收敛。

| 场景 | 审理素材 | 阻断分类 | reviewer 原始报告路径 | 最终复盘结论路径 |
|------|---------|---------|---------------------|----------------|
| **小说章节**（§④ 阶段复盘） | 全卷正文、世界观、人物卡、伏笔表、上下文包 | 世界观违反 / 人设违反 / 伏笔悬空 / 时间线倒流 / 记忆矛盾 | `05_复盘/<日期>-<主题>-round-N.md` | `05_复盘/第N卷_复盘.md` |
| **小说单场**（§③ 写后审） | 单场正文、上下文包、在场角色卡 | 同上（单场范围） | 同上 | `03_正文/第N卷/_审查后_第M章.md` |
| **非小说**（治理/计划/脚本等） | 被审文件 + 相关规则文档 | 视场景定义——每次 spawn reviewer 前由 Orchestrator 在 prompt 中声明 | `05_复盘/<日期>-<主题>-round-N.md` | 同左（不另建文件，回溯写在同一份 round-N.md 末尾） |

> 非小说 converge 不绑 `第N卷` 命名是因为它和小说进度无关——用日期+主题命名即可。

## 与 AGENTS.md 的对接

- AGENTS.md §④ 阶段复盘引用本文件作为 converge 操作指南
- AGENTS.md 完工检查清单的"正文一致性"项引用本文件的阻断分类作为判据
- 写后审（§③）是本协议的**单场轻量版**——素材只含当前场，阻断分类同上，最多 3 轮。结论落盘 `03_正文/第N卷/_审查后_第M章.md`（schema 见 [[docs/frontmatter-schemas]]；verdict 取值同本协议 = 可收敛|需修复）。该 artifact 仅证留痕，不证审查质量。
