# 小说写作 AI 协作规范

> `AGENTS.md` / `CLAUDE.md` / `GEMINI.md` 内容一致；只编辑本文件，改后跑 `agent_links.py repair`。
> 本文件只放**规则和指针**，细节去子文档找。

## 项目概述

一部正在创作中的长篇小说。Agent 是**受托的执行者 + 质量守护者**——按四阶段工作流推进剧情，用宪法审查 + converge 迭代收敛防止漂移（吃书）。

`00_世界观/核心设定.md` 的硬设定不可轻改——任何人（含 agent 和用户）要改都须走多轮独立评审。

## 初始化

新克隆 / 内容缺失 → `template.py init`（不覆盖已有文件）；开新书 → `template.py reset --all --force`（旧内容仍在 git 历史里）。

## 就绪自检（接到"推进剧情"任务前强制执行）

四项任一不满足 → **拒绝推进正文，引导用户先完成设定**：

1. `00_世界观/核心设定.md` 世界法则段非空
2. `01_大纲/主线.md` 主线一句话已填写
3. `02_人物/_索引.md` 至少一个实际角色
4. `docs/style-locked.md` 视角和时态已选定

> 失败时按 [[docs/CURRENT]] '下一步'清单逐项引导。文件不存在 → 先 `template.py init`。

## 引导模式感知

引导世界观/大纲/角色创建前，先探测用户处于**有限模式**（想写完小说）还是**无限模式**（只想建世界玩）——2-3 轮内自然插入，不做成问卷。无限模式**不触发就绪自检→推进剧情管道**，改走世界建造流程。

完整策略、切换信号、对话模板见 [[docs/writing-style]]「有限/无限框架的引导策略」+ [[00_世界观/_设计方法]]「引导对话原则」。

**零素材开场**（用户只说"我要写小说"）：**先给后问，禁止方法论倾倒**。追问只会得到"我不知道"。给 3-4 个具体起点（世界/人/画面/情绪，见 [[01_大纲/README]]「模式零」）让用户反应——赞同或反对都是有效信号。不列模式清单。

## 行为规则

### Compact 恢复（强制）

上下文含 "continued from a previous conversation" → 先读 [[docs/CURRENT]] 确认任务状态；完成前**禁止写操作、禁止有副作用的判断**。

### 硬约束

标注含义：`[阻断]` 脚本检出即拦 · `[提醒]` 脚本给信号、你判断 · `[你负责]` 无脚本覆盖。

- **记忆回写** `[阻断]`：每卷/关键场景后，受影响角色的记忆段必须更新
- **人设演化记载** `[提醒]`：稳定内核或身份矛盾任一字段改变 → 「演化记录」追加触发事件、代价、新旧状态；禁止覆盖历史。**是否构成演化由你判断**
- **伏笔登记** `[你负责]`：新伏笔立即登记（open），回收后改 closed。**不登记 = 不存在 = 收不回来。** 脚本只查已登记条目的格式
- **关系同步** `[提醒]`：有意义互动后 `relationship.py set/update`，卷末 `regenerate`
- **标签同步** `[提醒]`：角色创建或能力变化后更新 tags，卷末 `check_tags.py regenerate`
- **受保护文档** `[阻断]`：世界观硬设定、`docs/style-locked.md` 等的改动须带 `[governance]`。清单见 `.githooks/commit-msg`

### 默认偏好

- **先读后改**：改任何文件前先读取
- **Occam**：如无必要，勿增实体
- **Bitter Lesson**：通用方法优于硬编码先验。语义一致性交 LLM + converge
- **作者分离**：Agent 写的标 `model` / `generated_at`，用户写的不标。章节缺 `model` 又缺 `author: human` → pre-commit 阻断
- **执行模式**：单场对话内的小修直接执行；跨卷跨角色走四阶段闭环

## 四阶段工作流

接到"推进剧情"任务 → 先跑就绪自检 → 按下表执行。**细则见 [[docs/workflow]]。**

| 阶段 | 做什么 | 产出 |
|------|--------|------|
| ① 宪法审查 | 对照世界观与主线评审方向，冲突等用户裁决 | `_工作/_审查_第M章.md` |
| ② 写前准备 | 组装上下文包：在场角色 + 状态 + 场景决策 + 达成断言 | `_工作/_准备_第M章.md` |
| ③ 推进执行 | 写正文 → 独立 reviewer 审 → 维护子代理回写 | 正文 + `_工作/_审查后_第M章.md` |
| ④ 阶段复盘 | 卷末 `check_all.py` + converge 审计至零硬阻断 | `第N卷_复盘.md` |

## 提交规范

Conventional Commit（`feat:`/`fix:`/`chore:`）。完成一卷或关键场景后主动提交。

## 文档维护原则

1. **不重复**：同一信息只在最合适的位置出现一次
2. **无补丁感**：只描述当前的自洽规则，不留演进痕迹（"原为…现改为…"/"v2 新增"）。新内容融进既有结构并重排编号，不追加在末尾。变更史归 CHANGELOG 与 `docs/plans/completed/`
3. **只记正文里读不出来的东西**：世界观、大纲、人物内核、设计决策
4. **CHANGELOG**：用 `python scripts/changelog.py titles/show/add/recent`，不读全文
5. **计划落盘**：跨卷/多角色的任务在 `docs/plans/active/` 写计划，完成后移 `completed/`

python scripts/check_all.py --quiet
